# Sound-change chains

Write an ordered list of sound changes from OIA to a daughter lect, apply it to every etymon, and
score the output against the attested reflexes. Everything runs from `data/` and needs only the
stdlib, except plotting and the report builder, which use the `plots` dependency group.

| file | what |
|---|---|
| `sca.py` | rule parser + applier; the rule syntax is documented at the top |
| `extract.py` | builds `pairs/OIA-<stem>.tsv` from `cldf/` (inherited `reflex` edges only; 80/20 train/test split by a hash of the etymon) |
| `evaluate.py` | `score`, `apply` (derivation trace), `suggest` (best next rule on train), `probe` (vowel outcomes by syllable position, Vedic accent, next vowel and weight), `frontier` (rule ablation; retired from the pipeline), `induce` (greedy baseline) |
| `synth.py` | cross-lect synthesis: `table`, `tags`, `orders`, `orderagg` |
| `languages.tsv` | the 152 lects in scope: Language_ID, file stem, group, clade, #etyma |
| `CATALOG.md` | the shared tag vocabulary every rule line carries (`; @tag — note`) |
| `rules/chains.sc` | the hand-written chains of all 151 lects in one file; each line belongs to the lects its `[…]` selector names (lects, families as `%set`s, exclusions) or to all (see *Family files*) |
| `families.py` | `merge` one-lect files into family files, `unite` family files into one, `explode` lects back to one-lect files, `check`, `diff`, `shared` (lines most of a family has) |
| `rules/auto/` | greedy induction baselines (generated by `run_auto.sh`) |
| `notes/<group>.md` | each group's findings, chronology evidence and data problems (`BRIEF.md` is the brief) |
| `results/` | `summary.csv` (scored directly from each chain), old frontier CSVs, `tags.csv`, `orders/`, `order_consensus.csv`, `chronology_stages.csv`, `nuristani-strata.csv` |
| `plots/`, `report/` | figures and the family report (`report/index.html`, built by `report/build.py`) |

The file stem is usually the Language_ID. IDs that differ only by case get a suffix, because
file names are case-insensitive on macOS: `As` → `As-Ul`, `as` → `as-ll`, `Ko` → `Ko-Ul`.

```bash
python sound_changes/extract.py --all-min-etyma 100 --outdir sound_changes/pairs 2> sound_changes/pairs/_index.tsv
python sound_changes/evaluate.py score sound_changes/rules/OIA-Pk.sc --loo       # + worst misses, residual confusions
python sound_changes/evaluate.py suggest sound_changes/rules/OIA-Pk.sc
python sound_changes/evaluate.py apply sound_changes/rules/OIA-Pk.sc 'prásārayati'
python sound_changes/evaluate.py frontier sound_changes/rules/OIA-Pk.sc --out sound_changes/results/OIA-Pk.hand.frontier.csv
sound_changes/run_auto.sh                                # greedy baselines for every lect
python sound_changes/synth.py table && python sound_changes/synth.py tags
python sound_changes/synth.py orders --workers 3 && python sound_changes/synth.py orderagg
python sound_changes/plots/chronology_graph.py
uv run --group plots python sound_changes/plots/synth_figures.py
uv run --group plots python sound_changes/report/build.py
```

## Shared changes (inlined 2026-10-07)

Every chain now lives in one file, so a change shared by many lects is simply one line with a wide
selector (`[hindi rajasthani-gujarati -W] …`). The earlier indirections are gone from the chains:
`use NAME` (central definitions in `changes.sc`) and `include BLOCK` (shared sequences in `blocks/`)
were inlined line by line (`tmp/sound_changes/families/inline.py`), each line keeping its notes and
a marker of where it came from, `(changes.sc NAME)` or `; ── block NAME ──`. Every lect's compiled
chain was checked identical, expanded classes included. Shared rules that relied on `changes.sc`'s
standard `G`/`Nasal` keep that meaning through the `G_std`/`Nasal_std`/`CnoR_std` classes where a
lect of the line redefines `G` or `Nasal`. The library is archived in
`tmp/sound_changes/backups/library-20261007/`; the engine still supports `use`/`include` (tests,
candidate files), but the live chains do not use them.

Classes are declared once for every lect at the top of the class block; the lects whose consonant
inventory differs redefine `G` (S, Marathi–Bhil, West Pahari, Eastern) or `Nasal` (Nuristani)
right after it.

### Sporadic changes (`optional:`)

`optional: RULE` (or `optional: use NAME`) marks a lexically sporadic change: the derivation forks where
the rule applies (with / without), identical forms merge, and the extension-aware and verb scores take the
best form per reflex. Admit one only if it beats a same-shape placebo
optional rule. Shared ones: `rt-retroflex-optional`, `ks-cch-optional`, `dental-retroflex-optional`,
`r-a-optional` (notes/blocks-round-summary.md § Sporadic).

## Family files

All chains live in one file, `rules/chains.sc` (2026-10-05; first one file per family, then united).
A rules file of this kind opens with `%lects STEM …` and names subsets with `%set NAME = …`; in
`chains.sc` the sets are the families (the Group column of `languages.tsv`). Every other line is an
ordinary chain line, optionally prefixed with a lect selector:

```
%lects H Brj Aw SSr NDu
%set west = Brj SSr              ; a named subset
include mia-core                 ; every lect
[Aw NDu] use hiatus.a.ic         ; only Awadhi and NDu
[-SSr] include nasals-m-nasal-v  ; every lect but SSr
[west -SSr] use length-loss.aa   ; a set minus a lect
[hindi rajasthani-gujarati -W] … ; two families but one lect
```

A lect's chain is the file read with only its own lines, in order, so `Rule.line` is a line of the
shared file. Several such files may sit in `rules/` (each lect listed in exactly one). A selector naming an unknown lect or set is an error, not a silent drop. Tools still
address a lect as `rules/OIA-<stem>.sc`: when no such file exists, `sca` finds the family file in the
same directory that lists the stem (`sca.resolve_lect`, `sca.lect_paths(dir)` enumerates lects,
`sca.lect_text(path)` gives the chain as a one-lect file, `sca.source_lines(path)` the lines
`Rule.line` indexes). A real `OIA-<stem>.sc` is still read as a one-lect file, so candidates and
snapshots keep working; tools that rewrite a chain in place must edit the family file
(`families.insert_lines`, `families.drop_lects`) and refuse a family lect otherwise
(`sca.require_one_lect_file`).

When a change belongs to most of a family, prefer widening its selector (or dropping it) to adding
a near-duplicate line: that is how the smaller lects stop missing shared changes.
`families.py shared` lists the lines most of a family has, with the lects that lack them.

## Rule files

Besides rules and classes, a file can carry two directives:
- `%exclude-source KEY` drops that source's pairs from evaluation (for unusable sources);
- `%source KEY … %end` wraps rules that run after the chain only when scoring that source's
  pairs, for per-source transcription. They do not count as chain rules.

A `repeat:` prefix reapplies a rule until the word stops changing. An `if:` prefix restricts a
rule to words with (or, with `!`, without) a word-level flag: `verb`, `numeral`, `starred`,
`root`, `accented`, derived per etymon from its glosses and headword (`evaluate.word_flags`).
`%gold-drop tone` strips tone marks from a lect's attested forms.

Environments can use `C*` (zero or more), so syllable-level conditions are expressible: first
syllable `# C* _`, final syllable `_ C* #`, next vowel `_ C* a`, pretonic `_ !#* Acc`. `Acc`,
`Long` and `Short` are built-in vowel classes; classes support set difference
(`Stop - t tʰ`); targets may contain optional tokens (`(a) (y) a t i`).

## Metric

Everything is scored per segment: the CDIAL grapheme profile treats `ḍʰ`, `r̩` and `ā́` as one
segment each. The main metric is **NED**, the edit distance divided by the length of the longer
form, averaged over reflex pairs (an etymon with three reflexes counts three times). The report
also gives the raw edit distance and the exact-match rate. Before comparison, both sides are
canonicalised (`sca.canon`): `ai`/`au` are split into two vowels, because in MIA spelling they
are hiatus (`tarai`). The attested side is also normalised (`sca.gold_tokens`):
- the diaeresis `ü` is read as `u`;
- parenthesised optional letters, homonym digits and stray combining marks are dropped;
- stress accents on vowels are dropped (never the acute of `ś`, `ź`);
- lax-vowel letters are folded (ʌ ə → a, ε ɛ → e, ɪ → i, ɔ → o). This is a lenient scoring
  choice, not a claim about the house transcription, which keeps ə for Dardic and ɛ/ɔ as vowels.

Fragments containing `°` are excluded at extraction.

**Headline metric (from 2026-09-30): the extension-aware NED below.** The plain NED of the bare
headword, and its bare-headword accent and tone scores, are deprecated. It scored a form that is
rarely the attested citation form (no stem extension, no verb formation) and applied every sporadic
rule unconditionally. `score_all.py`, `gates.py` and `evaluate.py score` no longer report or gate
it. The legacy `frontier`, `induce`, `suggest` and `probe` commands still optimise it and are kept
only for the old Prakrit frontier plots.

### Extension-aware score (unified, from 2026-09-30)

The score. Every headword is run through the **full** chain (every rule, `@morph` citation rules
included; sporadic `optional:` rules fork) as the bare headword, with every MIA noun extension
(`evaluate.EXT_MENU`, replacing the final vowel; the variant drops the `verb` flag and carries `ext`),
and with every OIA verb formation (`evaluate.VERB_MENU`, on the root of a -ti/-tē present or else the
stem; the variant carries `verb`, `vform`, `ext`), plus a lect's own `%ext-menu` / `%verb-menu`
items (`evaluate.menu`). Each attested reflex is scored against its closest candidate. Verb formations count only for verb
etyma, or for reflexes glossed as verbs ("to …", the denominative; `evaluate.verb_ok`; restored
2026-10-01). Noun extensions are offered for every headword, and no rule is ever switched off. The "verb" score is this score restricted to verb etyma.
`derive.py` traces the same chosen candidate.

Earlier description (pre-unification), kept for the menu's history:


`score --ext` and `synth.py ext` (→ `results/extension.csv`) report a third metric. The headword is
also run through the chain with each MIA stem extension of a fixed menu (`evaluate.EXT_MENU`:
-aka, -akka, -ikā, -ikka, -iyaka, -uka, -aḍaka, -allaka, -araka and neuter -akam, replacing its
final vowel; verbs are never extended; the variant carries the word flag `ext`, so a citation rule
written for bare headwords can say `if:!ext`),
and each attested reflex is scored against its closest variant, one choice per reflex because
several endings often coexist. No cost is charged for an extension, so the score is optimistic;
it is the headline score (its optimism bounded by placebo-tested menu items), reported with the
share of reflexes that chose each ending. Verbs have their own menu (`evaluate.VERB_MENU`): the headword's root (minus
-ati/-atē/-ayati/-ōti/-ti) plus a present, verbal-noun, infinitive, gerundive or participle suffix
(-ati, 1sg -ami, causative 1sg -ayāmi, -anaka, neuter -anakam, -aṇa, -anīya, -tavya, neuter -tavyakam, seṭ -itavya and -itavyakam, -ita, -itum, geminate -ikka, the causative verbal noun -āpanaka/-āpanakam (beat a stable-consonant placebo -āranaka in 16 lects vs 5), the causative gerundive -āpitavyakam (G -āvvũ, Or -āibā; neutral elsewhere); a lect may add its own formations with a `%verb-menu +ITEM …` line when the item beats a same-shape placebo on train and test in that lect (root + -aka in B, Marw, S, …; -alla in Bhoj; passive -iyanakam in N, Ku, D, kc, bhad) — added globally they only leak chance fits, or the bare root; a reflex glossed as a verb ("to …") of a non-verb headword may also take these formations on the noun stem (`d:` variants, `evaluate.denominal`: ārta + -anakam > S āṭaṇu), while a blanket noun-menu -anaka/-anakam scored no better than a placebo suffix; for verbs every @morph citation rule, %source tails included, is switched off, so the citation form must come from the menu by regular sound change), run through the lect's chain
so that it must derive the lect's own citation form; choices are reported as `v:SUFFIX`.

### Accent score

A second metric, **accent NED**, keeps the accent. It is computed only on attested forms that mark
one (any lect: a source that writes no accent is simply not accent-scored), with every accent
notation (acute, grave, circumflex, caron, contour tones) read as "this vowel is accented"; the score is
the accent-blind edit distance plus 0.5 once when the accent is missing or misplaced (the same
cost either way, so leaving a word unaccented is never cheaper than a guess). The prediction's accent comes from the latent accent
tier (see the header of `sca.py`): `$1-acc` hides the Vedic accent instead of deleting it, and
`$1+stress` rules place an accent, both without changing what any rule matches, so the
accent-blind NED is unaffected. `%accent vedic` (or `--accent-model vedic`) shows the Vedic
accent carried through the derivation wherever no rule placed one; the default shows only
rule-placed accents. `score` and `frontier` report both metrics; `synth.py accent` writes
`results/accent.csv` (no accent / chain / Vedic for every lect with accent-marked forms).

## Frontier

The rules-vs-score frontier is retired: summary scores (`synth.py table`) are computed directly from each chain, and the report no longer shows rule-ablation curves or the equal-rule-count greedy comparison. `evaluate.py frontier` still works on demand.

- **Hand rules:** `frontier` does greedy backward elimination on the train split. At each step
  it drops the rule whose removal costs least, and the rest keep their order. The resulting
  (#rules, test score) curve approximates the Pareto frontier: exhaustive search over all 2^N
  rule subsets is infeasible.
- **Automatic baseline:** `induce` adds, one rule at a time, whichever single-segment change most
  reduces train NED. Candidates are the most frequent Levenshtein edits between the current
  output and the attested forms, each optionally conditioned on a neighbouring segment, on V/C,
  or on `#`. Candidates are merged into one set rule only when they share an output over
  segments of one kind, or share an `align.describe` change category.
- **No-change baseline:** the zero-rule point of both curves (the etymon itself).

## Ordering evidence

`synth.py orders` tests every pair of phonological rules i < j in a chain with the two
single-rule moves that reverse them (j to just before i, i to just after j). If both raise train
NED, the lect requires i before j; if both lower it, the reverse fits better; mixed results are
not recorded. `orderagg` pools the results by tag across lects, and `plots/chronology_graph.py`
layers the well-supported orders into stages.

Names are the main tag plus only what distinguishes a change from others with that tag: the
affected segments and/or the environment (`int-stop-loss.kg`, `s-h.intervocalic`), numbered only as
a last resort (`rename_changes.py`). `equivalence.py` finds rules that behave identically on the
real inputs and so are candidates for one central change.

## Derivations for the Jambu app (`derive.py`)

`make all` runs `sound_changes/derive.py` after `align.py`. It replaces the naive Indo-Aryan
alignment: every form whose rank-1 chain reaches a CDIAL headword through a `reflex` edge (loans are
skipped) is derived with its lect's chain, or, for a dialect without one, a sister chain named in
`chain_borrow.tsv` (a hand table; old stages borrow the modern chain and are approximate). The
variant is the one the extension-aware score picks: bare headword, a noun extension (full rules), or
a verb formation (every `@morph` rule and `@morph` source tail off).

Per form it records the trace (each rule that changed the form, and the form after it) and composes
the per-step diffs into segment columns, so each alignment column names the rules that rewrote it;
the prediction is then aligned to the attested form (NW) and remaining differences are marked `?`.
Outputs in `cldf/`: `alignments.csv` (IA rows replaced), `derivations.csv` (trace as one edit per
step: `ref pos ndel seg…`), `sound_rules.csv` (per chain rule: order, text, central name, change
identity, tags, note, firing counts), `sound_chains.csv` (per lect: chain used, scores). The static
DB loads them as `sound_rule`, `sound_chain` and `sound_deriv` (see
`jambu-static/scripts/build_static_db.py`); entry pages show the trace, language pages the chain,
the correspondence explorer can group outcomes by rule, and the isogloss view compares lects by
shared changes.

## Scoring conventions (from 2026-09-29)

Headline scores (extension-aware NED, verb-menu NED) compare segments exactly, with two
normalisations only: every accent/tone mark on a vowel is dropped (acute, grave, vertical line,
circumflex, caron, contour tones — the accent score scores them), and spelling variants of one vowel
letter are unified (ε → ɛ, ǝ → ə, υ → ʊ). Vowel qualities are never merged: ə ʌ ɛ ɔ ɪ ʊ are distinct
from a e o i u (they used to be folded to house vowels). Where one source writes a lax/open vowel for
the same phoneme another writes plainly, the lect file handles it with an `@notation` rule in a
`%source` block; where the quality is regular, the chain derives it. The accent score keeps the marks
and scores accent position; `ext_acc` scores the accent of the variant the extension-aware score picks.

**Several outcomes:** `X > A | B / env` states a change whose outcome varies by word (MIA doublets, regional
mixtures): the derivation forks into every outcome and each reflex is scored against its best fork, like
`optional:` (which is `X > A | X`). A single derivation takes the first outcome. derive.py traces the
outcome a reflex used, and per-lect branch shares come from tmp/sound_changes/branches/branch_stats.py.
Example: `{s ś ṣ} m > mʰ | s s` (blocks/mia-sm.sc).
