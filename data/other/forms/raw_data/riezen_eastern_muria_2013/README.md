# Eastern Muria numeral table (source-stage audit)

The primary page is Eugene Chan's [Eastern Muria numerals](https://lingweb.eva.mpg.de/channumerals/Muria-Eastern.htm), credited to **Mrs. Irene van Riezen, SIL International, 20 December 2013**. This package uses exact `raw/Muria-Eastern.htm` from immutable [numeralbank/channumerals v1.0.1](https://doi.org/10.5281/zenodo.15649312). Its raw HTML was downloaded 12 February 2019 under CC BY 4.0. Checked-in HTML is 26,777 bytes, SHA256 `2a7bdc4868c7c11d2fecc0cfe6f1ad69bfd9591c1f5683aeb1b74881cebbf558`; archive ZIP SHA256 `d40ef57924f47e9d3a777955328497d4b4bfe7b4f3344211993c9b21688bfd66`. OCR did not contribute; the importer parses the original HTML cells, not later archive segmentations.

The table has **20 rows × two numbered cells = 40 prompts** (1–30, 40–90, 100, 200, 1000, 2000). **39** have complete secure readings. The printed 29 cell `ʊnt̪is]` has an unmatched closing bracket; it is **held** verbatim in the audit rather than silently removing punctuation or treating it as phonology. All cells and markup, prompt numbers, row/column, status, source qualifiers, and output keys are in `audit.jsonl`. A seeded 20-cell review recorded **0/20 material errors**, including the held 29 cell; first/last cells, two local Hindi notes and source arithmetic parentheticals were inspected separately. Parenthetical arithmetic at 40–200 is source commentary, not a component relation. The entire table is target data; there is no control column.

The source explicitly says “as in Hindi” beside 7 and 21; only those two installed forms carry `loanword`. Its general note says a Hindi numeral system is mixed with native terms “after six,” while also describing 1–5 as Dravidian. That prose does not securely scope a loan claim to every later individual cell, and the `after six` boundary is internally awkward given printed 6. No donor-form, etymon, or component edge is inferred. The source IPA-like readings remain verbatim in raw `Original` and `Phonemic`; a source-specific profile maps known phonetic signs to house display spelling, preserving source distinctions such as dental `t̪` and open `ɔ`. No native script or speaker/site is provided.

[Glottolog](https://glottolog.org/resource/languoid/id/east2340) lists **Eastern Muria** `east2340` as a spoken L1, matching the printed source label and its broad Chhattisgarh, India location. Exact elicitation site and coordinates are absent, so the new canonical has no point and no invented dialect. Jambu already has generic-Gondi dialect `muria` with Glottocode `muri1262`, but [that Glottolog node](https://glottolog.org/resource/languoid/id/muri1262) is a **family-level Muria grouping**, not this precise L1. Its **809 compiled generic-Gondi rows** remain unchanged pending a full-build source-by-source identity/migration review. After source-profile conversion, zero of the 39 new form+gloss pairs exactly match those 809 old `muria` rows; nine pairs match other generic-Gondi site attestations. No prior citation to this 2013 table was found, so this is not a same-print reimport. The new canonical does not imply migration of historical rows.

`import_source.py` produces source-local `draft.csv` and `audit.jsonl`, and only `--install` writes the dated source CSV. The installed package uses `data/other/forms/20260925-riezen-eastern-muria-numerals.csv/.yaml`, bibliography key `riezen2013easternmuria`, and `conversion/riezen-eastern-muria-2013.txt`. `Parameter_ID` is blank because the page makes no resolvable etymon claim. Full `make all`, full suite, generated CLDF identity/reference/graph checks and browser QA remain deferred under the user's no-build/no-remote instruction.
